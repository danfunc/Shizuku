# CPU task と GRANT 履歴

`task` は実行 context ではなく、CPU 管理層が保持する実行権の履歴帳。
コア × 実行優先度に一つ配置する。スレッドのスタックを保持せず、貸し手の
スレッド番号・世代・残サイクル数と、タイマの未計上区間を保持する。

## 現行ポートへの接続

RP2040/RP2350 の現行実装は各コアの thread-mode 実行系列を priority slot 0
として扱う。SVC / SysTick / PendSV の IRQ 優先度を添字にしてはいけない。
これらは同じ実行系列の貸与・計時・返却を処理する入口だからである。

`cpu_manager` の第4テンプレート引数で台帳の優先度数を構成できるが、現行
カーネルは slot 0 を使う。複数優先度の実行系列を同時に保持するポートは、
現在スレッドの管理、台帳の選択、優先度遷移時のタイマ保存・復元も接続する必要がある。
この変更で割り込み上の任意の context 切替まで実装済みとはしない。

## 無効になった返却先

GRANT の巻き戻しでは、context を参照する前に世代と状態を検査する。
終了済み・再利用済みの貸し手を飛ばし、生存する外側の貸し手へ返す。
デバッガ停止中の貸し手には完了結果を保存するが、実行先には選ばない。
返却先が無ければ、設定された recovery thread を試す。そこも走れない場合、
生存中の借り手だけは継続できる。終了・停止した借り手は復活させない。
どこにも安全に復帰できない場合は fail-stop とする。

この検査だけではクロスコアの寿命管理を完結できない。破棄時の停止要求・完了応答、
thread から task への逆引き、専用 context 上での回収は
[非同期 object destroy](09_async_object_destroy.md) に記載した。
現行カーネルは複数優先度での誤使用を `static_assert` で拒否する。

## 検証

`bash tests/host/run.sh` でホスト用CPUモデルに実際のカーネル実装を接続し検証する。
ネスト予算、期限切れ、終了済み貸し手、世代の異なる枠、停止中の貸し手、復帰先を
失った借り手、コア別の履歴と優先度別の格納を確認する。既定でUBSanを有効にする。
対応するホストでは `SANITIZERS=address,undefined bash tests/host/run.sh` も使用できる。

これは実機の例外優先度・割り込み競合・MPUの検証を代替しない。
